## ⚠️ خطوة مطلوبة بعد هذا التحديث

### 1) تطبيق جداول المزامنة الأربعة الجديدة على Supabase

في المرحلة الأولى أضيفت 4 جداول كانت تعمل محلياً فقط إلى المزامنة السحابية:

- `documents` — المستندات المرفوعة
- `audit_logs` — سجل العمليات والتدقيق
- `contract_revisions` — إصدارات العقود المؤرشفة
- `custody_transactions` — حركة العهد (تسليم / إرجاع / تلف)

يجب إنشاؤها في مشروع Supabase:

1. افتح **Supabase Dashboard ← SQL Editor**.
2. الصق محتوى الملف `supabase_missing_tables.sql` **كاملاً**.
3. اضغط **Run**.

> هذا الملف آمن لإعادة التشغيل (`CREATE TABLE IF NOT EXISTS`) ولن يمس أي بيانات موجودة.
> يعمل أيضاً على تفعيل RLS لهذه الجداول الأربعة للمستخدمين المسجّلين فقط، دون أي سياسة `anon`.

### 2) (اختياري/تأكيدي) أعد تشغيل تقوية RLS

إذا كانت جداول المزامنة الأربعة قد أُنشئت قبل إعادة تشغيل `supabase_missing_tables.sql`،
فإن `supabase_rls_hardening.sql` أصبح يشمل الآن `contract_revisions` و `custody_transactions`.
أعد تشغيله نفس الطريقة السابقة للتأكد من عدم وجود أي سياسة `anon` متبقية.

## ✔️ التحقق من النشر

افتح تبويب **Actions** ← آخر تشغيل لـ *Deploy static content to Pages*:

- ✅ يجب أن تظهر خطوة **`Generate env.js from repository secrets`**
  وتطبع المضيف (مثل `abcdefgh.supabase.co`) مع المفتاح مُقنَّعاً `********`.
- ❌ فشل عند **`Verify required repository secrets`** ⇽ سرّ ناقص أو فارغ أو
  `SUPABASE_URL` لا يبدأ بـ `https://`.
- ❌ فشل عند **`Sanity check`** ⇽ لم يُحقن شيء في `env.js`.

ثم افتح: `https://malek9art.github.io/cntract/`

| شريط الحالة في شاشة الدخول | المعنى |
|---|---|
| 🟢 «الاتصال بقاعدة البيانات السحابية جاهز» | كل شيء تمام — سجّل الدخول بالبريد المصادق |
| 🔴 «الخدمة السحابية غير مُهيّأة في هذه النسخة» | المفاتيح لم تُحقن — راجع سجل Actions |
| 🟡 «لا يوجد اتصال بالإنترنت» | مشكلة شبكة لدى الجهاز |

> عند أول فتح بعد النشر اعمل تحديثاً قسرياً مرة واحدة (**Ctrl+Shift+R**) للتخلص من
> النسخة المخزّنة القديمة. بعدها يتولى النظام تحديث نفسه تلقائياً عند كل نشر.
