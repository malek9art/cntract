# نظام إدارة عقود الموظفين والعهد والمستندات | شركة أبو حذيفة للصرافة والتحويلات

نظام إداري ومالي متكامل لإدارة عقود العمل، الأصول، والعهد الوظيفية (الأجهزة، المعدات، المركبات)، إصدار محاضر الاستلام والتسليم والإرجاع، إدارة الرواتب بالريال اليمني (YER) والريال السعودي (SAR)، وتوليد وطباعة ملفات ومستندات PDF الرسمية عالية الجودة بهوية شركة **أبو حذيفة للصرافة والتحويلات**.

---

## 🌟 مميزات النظام المحدثة

1. **العمل بدون إنترنت (100% Offline-First) ودعم النشر على GitHub Pages:**
   - مبني بالكامل على معايير الويب الخالصة **HTML5 / CSS3 / ES6 Modules** بدون Node.js أو عمليات Compile.
   - مزود بـ **Service Worker (`sw.js`)** لحفظ كافة الأصول محلياً وتطبيق **PWA (`manifest.json`)**.
   - تخزين محلي كامل في **IndexedDB** لجميع الجداول.

2. **تخصيص الطرف الأول (صاحب العمل):**
   - إمكانية تعديل **اسم الطرف الأول الرسمي**، **اسم الممثل المفوض بالتوقيع**، و**صفة الممثل المفوض** مباشرة من شاشة الإعدادات.
   - انعكاس فوري وتلقائي على كافة العقود، محاضر الاستلام، كشوفات الفحص، وأقسام التوقيع والختم.

3. **الربط السحابي ومصادقة Supabase (عبر أسرار GitHub حصرياً):**
   - يتم حقن مفاتيح Supabase (`SUPABASE_URL` و `SUPABASE_ANON_KEY`) **تلقائياً من أسرار مستودع GitHub** أثناء النشر.
   - **لا يوجد أي إدخال يدوي للمفاتيح داخل التطبيق**، ولا يتم تخزينها في متصفح المستخدم إطلاقاً.
   - تسجيل دخول ومصادقة آمنة عبر البريد الإلكتروني وكلمة المرور، مع دعم إعادة تعيين كلمة المرور من داخل شاشة الدخول.
   - مزامنة سحابية ثنائية الاتجاه (رفع السجلات المحلية إلى السحابة / تنزيل واستيراد السجلات من السحابة).
   - استمرار العمل المحلي دون انقطاع في حال غياب الاتصال أو عدم تفعيل Supabase.

4. **بيانات نظيفة وجاهزة للإنتاج (Clean Production State):**
   - يبدأ النظام بقاعدة بيانات نظيفة (0 موظفين، 0 عقود، 0 عهد، 0 سيارات تجريبية) مع الحفاظ على القواميس الأساسية (البنود الـ 22، قوالب العقود، وشبكة الفروع).
   - توفير زر اختياري في الإعدادات: **"تحميل عينة بيانات تجريبية للاختبار"** و **"تفريغ وحذف كافة السجلات"**.

5. **محرك طباعة وتوليد PDF معزول واحترافي:**
   - برنامج تشغيل طباعة معزول (`Isolated Print Driver`) بحجم **A4 RTL** يضمن خلو المخرجات من أي أخطاء أو قص في الهوامش أو تداخل في التوقيعات.
   - علامة مائية رسمية لشعار شركة أبو حذيفة في خلفية المستندات المطبوعة.
   - تفقيط المبالغ المالية كتابة باللغة العربية (Tafqeet) بالريال اليمني والريال السعودي.

## 🔐 الربط السحابي عبر أسرار GitHub (إلزامي لتسجيل الدخول)

مفاتيح Supabase **لا تُكتب في الكود ولا تُدخل من شاشة الإعدادات**. مصدرها الوحيد هو
أسرار المستودع، ويتم حقنها في ملف `env.js` أثناء عملية النشر عبر GitHub Actions.

### 1) إضافة الأسرار

انتقل إلى: **Settings ← Secrets and variables ← Actions ← New repository secret**
وأضف السرّين التاليين:

| اسم السر | القيمة | مكانها في Supabase |
|---|---|---|
| `SUPABASE_URL` | `https://xxxxxxxx.supabase.co` | Project Settings ← API ← Project URL |
| `SUPABASE_ANON_KEY` | `eyJhbGciOi...` | Project Settings ← API ← Project API keys ← `anon` `public` |

> ⚠️ يجب أن يكون العنوان بصيغة `https://` وبدون `/` في نهايته، وأن يكون المفتاح هو
> مفتاح `anon public` وليس `service_role` (الأخير سري ولا يجوز نشره في المتصفح).

### 2) تفعيل النشر عبر GitHub Actions ‼️

هذه الخطوة **ضرورية** — إذا بقي النشر على الوضع القديم (Deploy from a branch) فلن يتم
تشغيل أي بناء ولن تُحقن المفاتيح، وستفشل شاشة تسجيل الدخول دائماً.

1. **Settings ← Pages**
2. في **Build and deployment ← Source** اختر **GitHub Actions** (بدلاً من *Deploy from a branch*).
3. احفظ.

### 3) تشغيل النشر

ادفع أي تعديل إلى الفرع `main`، أو شغّل النشر يدوياً من:
**Actions ← Build & Deploy to GitHub Pages ← Run workflow**.

سيقوم الـ workflow الموجود في `.github/workflows/deploy-pages.yml` بـ:
- التحقق من وجود السرّين وإيقاف النشر برسالة خطأ واضحة إذا كان أحدهما ناقصاً.
- توليد ملف `env.js` وحقن القيم فيه.
- إضافة بصمة زمنية لكسر الكاش (`env.js?v=...`) وتحديث نسخة الـ Service Worker.
- رفع الموقع ونشره على GitHub Pages.

### 4) تجهيز قاعدة البيانات والمستخدم

1. **SQL Editor** في Supabase ← نفّذ `supabase_schema.sql`.
2. **Authentication ← Users ← Add user** ← أنشئ المستخدم وفعّل *Auto Confirm User*.
   - أو عطّل **Confirm email** من: Authentication ← Providers ← Email.
3. نفّذ `supabase_link_user.sql` لترقية المستخدم إلى مدير عام.
4. **موصى به أمنياً:** نفّذ `supabase_rls_hardening.sql` لمنع الوصول للبيانات بدون تسجيل دخول.
5. **Authentication ← URL Configuration** ← أضف رابط الموقع
   `https://<username>.github.io/cntract/` في **Site URL** و **Redirect URLs**
   (مطلوب حتى يعمل رابط إعادة تعيين كلمة المرور).

## 🩺 حل مشاكل تسجيل الدخول

| الرسالة الظاهرة | السبب | الحل |
|---|---|---|
| «الخدمة السحابية غير مُهيّأة في هذه النسخة» | لم تُحقن المفاتيح (`env.js` فارغ) | تأكد من الأسرار + أن مصدر Pages هو **GitHub Actions**، ثم أعد تشغيل النشر |
| «البريد الإلكتروني أو كلمة المرور غير صحيحة» | بيانات خاطئة أو المستخدم غير موجود | أنشئ المستخدم من لوحة Supabase أو استخدم «نسيت كلمة المرور» |
| «لم يتم تأكيد البريد الإلكتروني» | خيار Confirm Email مفعّل | فعّل *Auto Confirm* للمستخدم أو عطّل الخيار |
| «تعذر الاتصال بخادم Supabase» | `SUPABASE_URL` خاطئ أو المشروع متوقف | تحقق من العنوان ومن حالة المشروع (Paused) |
| «المفتاح العام مرفوض» | استُخدم مفتاح خاطئ أو مُدوَّر | انسخ مفتاح `anon public` من جديد وحدّث السر |
| النظام يعرض نسخة قديمة بعد النشر | كاش الـ Service Worker | أُصلحت في v1.1.0 (env.js يعمل بنظام network-first والتحديث تلقائي) |

للفحص السريع: **الإعدادات ← ربط قاعدة بيانات Supabase ← فحص الاتصال بقاعدة البيانات السحابية**.

## 🚀 نشر المشروع على GitHub Pages


1. ارفع المشروع إلى الفرع `main`.
2. اضبط **Settings ← Pages ← Source = GitHub Actions**.
3. أضف السرّين `SUPABASE_URL` و `SUPABASE_ANON_KEY` كما هو موضح في القسم أعلاه.
4. سينشر الـ workflow التطبيق تلقائياً على رابط GitHub Pages الخاص بحسابك.

> ملاحظة: وضع *Deploy from a branch* (النشر المباشر من الفرع) **غير مدعوم** لهذا المشروع،
> لأنه ينشر ملف `env.js` الفارغ بدون حقن المفاتيح فيفشل تسجيل الدخول.
